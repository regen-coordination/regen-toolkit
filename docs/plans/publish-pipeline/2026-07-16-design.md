# Publish Pipeline — validate → curated prod publish → standing dev→main flow — Design

**Date:** 2026-07-16 · **Status:** approved (operator, this date) · **Instance:** regen-toolkit
**Origin:** operator — "validate the processed content, PR it to `main` as public/published content, and connect the dev→prod pipeline." Sequenced with the Jul 16 toolkit call.
**Anchor:** [`docs/CONVERGENCE.md`](../../CONVERGENCE.md) · consolidation context: [`docs/plans/repo-consolidation.md`](../repo-consolidation.md)

## Problem

The toolkit's own KB (all 119 articles → 722 objects) and a 146-object handoff slice are processed and
committed on `regen-toolkit-os` (dev), all `raw`/review-gated. The public production site (`main`, via
Vercel) is ~190 commits stale. We want the refreshed site to become public, without leaking raw handoff
content or the internal org-os overlay, and with a **repeatable** dev→prod path — not a one-off merge.

## Key findings that shape the design (verified 2026-07-16)

- **The public site exposes only KB *aggregates*** (`/knowledge-commons`, `/convergence`,
  `/self-ingestion`, `/handoff` render counts / queue totals / by-type) — never individual raw object
  pages. So publishing does **not** require reviewing all 868 objects first; aggregates are public-safe.
- **`main` = Vercel prod**; **`regen-toolkit-os` = the working instance.** `main` is 0 commits ahead of
  dev (dev is a strict superset).
- Raw object detail pages are a **deferred** future step (needs review-promote first + new UI) — out of
  scope here.

## Decisions (brainstormed, operator-approved 2026-07-16)

| # | Decision |
|---|---|
| Scope | **A + C**: publish the site + aggregate KB layer now; site-level QA gate; object review-promote is a **standing** dev-side pipeline, **not** a publish blocker. (Not B — no public object-detail pages this pass.) |
| Curation | **Shape B (curated prod).** Public on `main`: site prose + `/convergence`, `/framework`, `/knowledge-commons` + article-KB **aggregates** (raw article YAMLs kept — toolkit's own content). |

## Dev-only paths (excluded from prod `main`)

The strip-list is an **explicit, editable constant** in the script, and the `--dry-run` manifest
(`what-publishes.txt`) is reviewed before any publish — so the boundary is inspectable, and edge cases are
caught by eye, not by getting the list perfect up front.

**Excluded (dev-only):**
- Data/notes: `kb-handoff/`, `kb-graph/`, `memory/`, `HEARTBEAT.md`, `MEMORY.md`
- Working/draft docs: `docs/plans/`, `docs/briefings/`, `docs/proposals/`, `docs/comms/`
- Preview pages: `src/pages/self-ingestion.astro`, `src/pages/handoff.astro` + their nav links

**Kept public:** the site itself (`src/` minus the two preview pages, `astro.config.mjs`, `public/`),
`packages/toolkit-framework/`, the Starlight content (`src/content/docs/` — the 119 articles),
`data/kb/` article objects + aggregate indices, and the **public-referenced** docs: `docs/CONVERGENCE.md`,
`docs/MASTER.md`, `docs/layers/`, `docs/canvases/`, `docs/reports/` (crosswalk + DoD are linked from
`/convergence`), `docs/CSIS.md`, `docs/onboarding/`.

*(Note: `docs/` is org-os coordination content, not Starlight site content — excluding a doc removes it
from the public repo, not from the deployed site. The deployed site renders `src/content/docs/`.)*

## Components

### 1 · `scripts/publish-to-main.mjs` — the curated projection
- **Guards:** clean working tree; on `regen-toolkit-os`; framework + kb-viz tests green. Abort otherwise.
- **Materialize** a release worktree off dev HEAD (isolated; never mutates the working tree — vault-safe).
- **Strip** the dev-only paths (above) from the worktree.
- **Regenerate single-corpus:** run `generate:kb-viz` with `kb-handoff/` absent → article aggregates only.
- **Verify** the projection builds (`npm run build` in the worktree). Broken prod build → abort.
- **Manifest:** write `what-publishes.txt` (sorted file list + object counts) — the reviewable
  "what would go public" surface, and the leak-check artifact.
- **Modes:** `--dry-run` (**default**): stop after the manifest, change nothing. `--publish`: commit the
  curated snapshot to `release/<date>` and open a PR to `main` (draft-and-present; human merges).
- Deterministic + idempotent (reuses the tested single-corpus kb-viz behavior).

### 2 · `main`-branch `.gitignore` backstop
The dev-only paths are added to a `.gitignore` that ships on `main`, so an accidental future merge/commit
can't reintroduce them. (Belt-and-suspenders with the script's strip step.)

### 3 · `docs/PUBLISH-CHECKLIST.md` — the site QA gate (C)
Signed (named human) in each publish PR description:
- **Frame-language pass** — spot-check new/changed public copy for Frame-1 (extractive/hierarchical) language (`docs/CSIS.md`).
- **Accuracy** — numbers reconcile (813 raw / 839 awaiting review), convergence claims hold, evidence links resolve.
- **Public-safety** — `what-publishes.txt` contains no `kb-handoff/`, no overlay, no preview pages.
- **Privacy / name-flagging** _(added 2026-07-19; the 2026-07-16 hard gate)_ — verify the
  name-flagging/removal feature exists + works **before** any publish that widens the public surface;
  scan `what-publishes.txt`-covered KB data (`data/kb/` ships public) for individual names — the T4
  schemas add first-class `person` objects and article-derived objects can name people. Task:
  `task-260716-luiz-name-flagging-privacy-gate`.
- **Build** — succeeds; no Starlight breakage.

### 4 · `netlify.toml` — dev preview build config
Build command + publish dir for the **full** dev site (no stripping), so `regen-toolkit-os` renders
everything (both corpora aggregates + preview pages) as per-commit deploy previews. Dashboard hookup is
the follow-on; the file is prepped this pass.

> _2026-07-19 note:_ until the org migration lands + Netlify is stood up, **`fork`/Pages is the interim
> dev-preview surface** — [`dev-instance-build.md`](../dev-instance-build.md) deploys the full dev
> instance there now. Netlify still retires it afterwards, as designed.

### 5 · Review-promote — the standing pipeline (no new tooling)
The framework's existing `review-promote` skill, named as the standing dev-side workflow. Cadence: a first
live tranche on the call (source-systems + high-risk boundaries + person/org fallbacks), then continuous.
As objects reach `reviewed`, prod aggregate counts shift on the next publish. No code here — a documented
cadence in `PUBLISH-CHECKLIST.md`'s "standing work" note.

## Sequencing

1. **Pre-call (build; no external effect):** `publish-to-main.mjs` (dry-run default), `PUBLISH-CHECKLIST.md`, `netlify.toml`. Run `--dry-run`; review `what-publishes.txt`.
2. **On the call:** walk `/convergence` (preview) → confirm shape-B curation → first review-promote tranche together → green-light prod publish.
3. **Publish:** `publish:main --publish` → PR → checklist sign-off → merge → Vercel deploys.
4. **Follow-on:** connect Netlify to `regen-toolkit-os` via `netlify.toml`; retire `fork`/Pages.
5. **Standing:** review-promote continues; each release = `publish:main` again.

## What gets built now vs gated

- **Build now (reversible, no external effect):** the script (dry-run default), the checklist, `netlify.toml`.
- **Gated on operator go / the call:** the actual `--publish` PR, the merge to `main`, the Netlify dashboard hookup, retiring `fork`/Pages.

## Testing / verification

- Script: unit-test the strip-list projection + manifest on a fixture tree; assert dry-run mutates nothing;
  assert the projection contains none of the dev-only paths and still builds.
- End-to-end: `publish:main --dry-run` on the real repo → `what-publishes.txt` shows the curated set, no
  dev-only paths, prod build green in the worktree.
- Vault safety: worktree isolation; the script never runs `stash`/`clean`/`reset --hard`; only the
  release worktree is mutated; auto-removed after.

## Out of scope (named, not built)

Public object-detail pages (the deferred "B" — needs review + UI) · a CI/Action wrapper around
`publish:main` (future; thin wrapper calling the same script) · the org migration (separate:
`repo-consolidation.md`) · reviewing all 868 objects (standing work, not a gate).

## Guard rails

Nothing reaches prod `main` except through `publish:main` + a signed checklist. Raw handoff content never
publicly exposed. `docs/MASTER.md` untouched. `--dry-run` default. All external steps draft-and-present.
Vault-safety rules on every worktree/merge/checkout.
